## 1. 首次使用与连接

- [ ] 空数据目录启动时显示引导，明确说明本机 Codex、仍需联网、使用现有 Codex 额度。
- [ ] “检查 Codex 连接”能显示可操作的结果；未安装、路径错误或未登录时能理解下一步需要修正什么。
- [x] “生成第一期”完成采集、筛选、显示与本地保存；下一次启动直接显示已保存的内容。
- [ ] 首屏顶栏的手动更新入口也能完成首次初始化，成功后按设置参加每日更新。
- [ ] 首次生成失败后仍能打开设置、修正路径或来源并再次生成；没有卡死或只能重启的状态。
- [ ] 演示模式始终有醒目标记，不把示例称为当天真实资讯，不调用 Codex。

## 2. 悬浮窗与快速扫读

- [ ] 在正常桌面启动时小窗位于右上角，并悬浮在浏览器、编辑器等普通应用窗口上方。
- [x] 392 × 650 的正常内容视图中，首屏可扫到至少两条完整精选；本次真实内容截图见验证记录，状态提示和其他数据组合继续验收。
- [ ] 精选只显示一段正文，优先关注理由，否则显示摘要；标题和正文各最多两行。悬停能查看完整标题、摘要与关注理由。
- [ ] 简讯标题和摘要各最多两行；追踪卡片摘要最多三行，另外的关注理由最多两行。
- [ ] 标签、来源和原始时间仍可识别；GitHub 仓库写“仓库创建于”，RSS/Atom 写“发布于”。日期缺失时明确显示未提供，不能用仓库创建、采集或生成时间冒充新闻发布时间。
- [x] 主窗圆角与细边框完整，没有不透明方角、文字出界、按钮遮挡或底部状态栏被挤出窗口。
- [ ] 深色与浅色都能看清正文、绿色强调、来源文字及悬停状态。
- [ ] 点击收起后出现右侧标签；鼠标经过不会自动展开，点击可以展开。拖动小窗后收起与恢复的位置合理。
- [ ] 菜单栏可以重新显示小窗、打开设置与退出；切换桌面、全屏应用及外接显示器的结果分别记录。

## 3. 阅读操作

- [ ] 点击每种卡片的标题或正文，用默认浏览器打开该条原始来源。
- [ ] 复制研究指令后可粘贴到文本编辑器或 Codex；内容包含正确标题、来源链接、摘要和研究要求，不自动执行研究或安装项目。
- [ ] 复制成功提示短暂出现后消失，不卡住界面，也不挡住后续点击。
- [ ] 来源状态可以展开；部分来源失败时，成功来源的内容仍可阅读，失败原因可见。
- [ ] 键盘能进入设置输入框并使用复制、粘贴、全选；图标按钮有可读的辅助功能名称。

## 4. 设置与自定义来源

- [ ] 修改兴趣、时间、时区和路径后点“取消”，原设置不变；“保存设置”成功后独立设置窗口关闭，重新打开能看到保存结果。
- [ ] 默认时区为 `Asia/Shanghai`、时间为 08:00。切换 Mac 系统时区不会改变这份显式时区设置。
- [ ] 关闭自动更新后，底部状态与离线提示不再承诺自动补更；手动更新仍可使用。
- [ ] 小时、分钟、时区、空兴趣及无启用来源等非法输入有清楚错误；错误出现在底部按钮附近，不藏在长列表下方。
- [ ] Codex 路径留空能自动检测；改为指定路径并保存后，连接状态与新路径对应。
- [ ] 添加公开 HTTPS RSS/Atom 来源后可启用、采集和保存；非法地址与重复地址有提示。
- [ ] 自定义来源可以删除；预置来源可以关闭。取消设置不应把草稿中的新增、删除或开关写入正式配置。
- [ ] 改兴趣与来源后手动生成，能看到新配置生效；已有简报不会因编辑草稿被清空。

## 5. 定时、离线与日期

- [ ] 应用运行且在线时，计划时间到达后生成当天一期；当天已有正式简报时，不因定时检查重复生成。
- [ ] 断网期间保留旧内容与日期；启用自动更新且已错过计划时，恢复网络后补更。
- [ ] 休眠错过计划后，唤醒且联网时能补更；退出应用或关机期间不会声称仍在更新。
- [ ] 北京时间日期、原文时间、生成时间分别正确显示；跨午夜任务、其他时区及夏令时边界由可注入时刻的调度测试覆盖，无需修改 Mac 系统时钟。

## 6. 失败恢复与额度控制

- [ ] 更新期间重复点击或从菜单触发更新，不会启动第二个并发生成任务。
- [ ] 顶栏更新按钮在运行时变为取消；取消后旧内容保留，任务与子进程能结束，按钮恢复可操作。
- [ ] 获取失败、无可用候选、Codex 失败或输出未通过校验时，保留上一期，错误可读且不截断。
- [ ] 只有生成类错误显示“重新生成”；打开浏览器、复制或保存设置失败不能出现会误导用户重新调用 Codex 的重试入口。
- [ ] 自动重试遵循间隔与每日尝试上限；触及上限后明确提示。手动重新生成仍由用户主动触发。
- [ ] 两个实例使用同一数据目录时不会并发调用生成；后启动的自动任务获取锁后会重新检查当天结果，避免重复生成。
- [ ] 生成成功但保存失败时仍能看到内存中的结果与保存错误，不因历史清理失败立即重复消耗生成额度。
- [ ] 最新文件损坏时能恢复有效历史；启动、设置错误或未完成更新不会以空内容覆盖已有简报。
