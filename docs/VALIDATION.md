## 自动检查

`./scripts/test.sh`：3 个测试套件，共 48 项；46 项执行通过，2 项需要显式启用的来源联网检查跳过。默认测试不调用真实模型、不使用账号额度。

| 范围 | 覆盖内容 |
| --- | --- |
| 来源解析 | RSS/Atom、相对链接、HTML 文本、重复链接、无效日期、只有 Atom 修改日期时不伪造发布日期 |
| 不可信内容 | DTD 与实体声明、UTF-16 输入、正文大小限制、危险链接、候选 ID 与模型输出校验 |
| 来源失败 | 无有效来源、全部失败的可读报告、取消、不泄露来源 URL 内的敏感参数 |
| Codex 子进程 | 未登录、不兼容、额度错误、缺失及超大输出、大量 stderr、超时与取消、包装进程及其子进程结束 |
| 日期与计划 | 显式北京时间、跨日期、夏令时跳时与重复时段、错过时间后的调度、凌晨手动生成不挡住早晨更新 |
| 重试与存储 | 自动调用每日上限及次日重置、退避、进程锁、损坏缓存恢复、有效空结果、历史成功但最新副本保存失败 |

`./scripts/build.sh`：Release 构建、`.app` 打包与 ZIP 生成通过。另行执行 `codesign --verify --deep --strict`、`plutil -lint` 和脚本语法检查通过。包使用本地 ad-hoc 签名。

GitHub Actions 工作流已启用，执行相同的离线测试和 Release 构建。首次云端检查发现 macOS Bash 3.2 对空参数数组的兼容问题，测试脚本已修复，并在本地验证 Xcode 和 Command Line Tools 两条参数路径。[修复后的云端验证记录](https://github.com/HeartY1ng/SideBrief/actions/runs/35010168748)和[所有运行记录](https://github.com/HeartY1ng/SideBrief/actions)可公开查看。

## 真实采集与生成

- 7 个默认启用来源实际采集成功，按配额得到 70 条候选。
- 在应用内使用已登录的 Codex 完成真实生成，第一期得到 5 条精选和 6 条简讯，共 11 条；没有为凑数生成“持续关注”。
- 日期修复后，用最终构建再次刷新成功，得到 3 条精选和 5 条简讯，共 8 条；刷新期间旧内容仍可阅读，新内容中缺少发布日期的条目明确显示“发布时间未提供”。两期均保留在本地历史中。
- 结果写入默认数据目录；退出后重新打开，直接恢复已保存内容。
- HN 聚合来源在本环境遇到 TLS 连接错误，预置为关闭，用户可自行启用。

真实来源与模型输出会随时间改变；上述条数是本次结果，不是每日固定数量或内容质量保证。

## 仍需人工覆盖

- 深色外观、全屏应用、多个桌面、不同缩放与外接显示器。
- 实际断网再联网、物理休眠再唤醒以及长期驻留；当前已覆盖核心调度、错误和恢复逻辑，尚未完成整夜现场观察。
- 全部设置组合、定制来源的完整界面流程、复制后粘贴及每类卡片的浏览器目标页面。
- Intel 与其他 macOS 版本、没有开发工具的新机器安装体验。
- Apple Developer ID 签名与公证。

上述场景列在[验收清单](UX-CHECKLIST.md)中，供后续设备测试继续记录。首版不含 API Key 模式、自动登录启动或多主题独立日报。
