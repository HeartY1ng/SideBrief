# 资讯来源与筛选规则

SideBrief 从设置中启用的公开来源获取内容，再交给本机已登录的 Codex 筛选、生成中文日报。资讯覆盖范围由这些来源决定。

## 默认来源

默认启用以下 7 个来源：

| 来源 | 地址 | 获取内容 |
| --- | --- | --- |
| OpenAI | [新闻 RSS](https://openai.com/news/rss.xml) | 官方新闻与产品动态 |
| Hugging Face | [博客 RSS](https://huggingface.co/blog/feed.xml) | 模型、工具与社区技术文章 |
| GitHub Blog | [博客 RSS](https://github.blog/feed/) | GitHub 产品、开发工具与技术文章 |
| Ollama Releases | [版本 Atom](https://github.com/ollama/ollama/releases.atom) | Ollama 仓库版本发布 |
| n8n Releases | [版本 Atom](https://github.com/n8n-io/n8n/releases.atom) | n8n 仓库版本发布 |
| Home Assistant | [博客 Atom](https://www.home-assistant.io/atom.xml) | Home Assistant 更新与项目动态 |
| GitHub · 新近活跃项目 | [公开仓库搜索](https://api.github.com/search/repositories?q=topic:artificial-intelligence+stars:%3E50&sort=updated&order=desc&per_page=15) | `artificial-intelligence` 主题、星数超过 50 的仓库，按更新时间请求最多 15 个结果 |

另外预置了 [Hacker News · AI](https://hnrss.org/newest?q=AI%20OR%20LLM%20OR%20agent&count=25)，**默认关闭**。这是由 hnrss 提供的聚合订阅，查询词为 `AI OR LLM OR agent`。可在设置中自行启用；它不计入默认的 7 个采集来源。

预置来源与默认兴趣一起偏向 AI 和开发工具。GitHub 搜索只是一个限定查询，并不代表 GitHub 全站热门榜，也不保证覆盖全部相关开源项目。

## 添加、关闭与删除来源

1. 展开小窗，点击底部的设置图标。
2. 在“资讯来源”中，用开关启用或关闭已有来源。
3. 在“添加 RSS / Atom 来源”填写名称和公开的 **HTTPS RSS/Atom 地址**，点击“添加”。网页首页通常不能代替订阅地址。
4. 点击“保存设置”。下次生成使用新配置，也可以回到小窗点击“立即更新资讯”。

自定义来源旁的减号可删除该来源；预置来源可关闭。当前界面不能直接编辑已有来源的名称或地址：自定义来源需要删除后重新添加。设置最多保存 30 个来源，包含关闭的来源，且至少启用一个。

本版没有订阅源登录、Cookie 或 API 密钥配置，应使用无需凭据的公开地址。程序会拒绝在 URL 中嵌入用户名或密码；查询参数中的秘密令牌也不适合放入来源设置。

界面的添加入口只支持 RSS/Atom。GitHub JSON 搜索由预置的专用解析器处理，不能把任意 JSON API 地址当作 RSS 添加。

## 一次更新如何选出候选

1. 同时最多请求 4 个来源；每个来源有约 20 秒的网络超时和 3MB 内容上限。
2. 解析 RSS/Atom 的标题、原文链接、日期及摘要或内容节选。无效的文章链接不进入候选；相对链接会按来源地址解析。重复链接会去重，常见跟踪参数和片段会被移除。
3. 每个来源内部优先选择最近 14 天的内容，再考虑日期未知和较早的内容。**14 天是一般资讯的排序优先级，不是统一删除旧文章的规则。** 无法解析或缺失的发布日期保留为未知，不用采集日期或 Atom `updated` 修改日期冒充发布日期。
4. 每源最多保留 12 条，按来源轮流取候选，合计最多 70 条，再排序交给 Codex。这样，文章很多的单一来源不会占满全部名额。
5. Codex 按兴趣生成“今日精选”“更多动态”“持续关注”。目标分别为通常 3～5 条精选、最多 10 条简讯、最多 2 条持续关注；资料不足时可以更少，不保证每天凑满。

“资讯源状态”里的条数是该源解析出的可用条目数，位于每源配额和总量筛选之前，因此可能大于实际送入 Codex 的条数。

### GitHub 日期和增长信息

GitHub 仓库另有明确的活跃度过滤：只有 `pushed_at` 可解析且处于最近 14 天的公开仓库才进入候选，对时钟偏差保留一天未来时间容差。仓库的 `publishedAt` 使用 `created_at`，最近推送时间写入活动说明；更新旧仓库不等于今天新建或发布了项目。

采集同时保留星数和 Fork 数。一次星数快照或一次推送不能证明“影响持续扩大”。生成规则要求有实际采用证据，或与历史日报中同一项目的指标进行有时间依据的比较，才可以描述增长；证据不足时不放入“持续关注”。第一版没有覆盖所有仓库的长期指标监控。

## 来源失败与离线

一个来源超时、限流或格式无效时，其余可用来源仍可生成当期日报。展开“资讯源状态”可查看来源名称、条数和失败原因；成功生成的这一期可能只覆盖部分来源。

如果全部来源都没有可用条目，则显示各源失败或空结果原因，并保留上一期。部分来源失败不会在当前日报中伪造补全内容，也不会单独补写已经生成的条目；后续生成会再次请求已启用来源。断网或休眠后的补更由应用的更新计划处理。

## 哪些内容交给 Codex

一次生成会传入：

- 你填写的兴趣描述。
- 经过配额筛选的公开条目：标题、来源名称、链接、日期、摘要或截短的节选，以及可用的项目指标。
- 最近最多 30 期本应用生成的日报摘要与指标，用于减少重复和比较变化。

这些材料通过已登录的 Codex 生成结果，会使用其可用额度；“本机调用”不代表模型在离线运行。应用不会为日报读取你的本地知识库或笔记。生成过程关闭额外联网搜索，并要求 Codex 只归纳已采集的材料。

## 来源事实与 AI 归纳

标题、摘要及“对你有什么用”的说明可能经过 AI 翻译或归纳。保留的来源链接用于回看原文；程序校验链接来自候选，并不等于已经验证文章内的每个事实。

为同一主题配置不同发布方的公开订阅，有助于拿到可相互核验的报道。核验同一事件时，可以在浏览器对照原始内容、发布日期与发布方。当前每张资讯卡只提供一个原始来源链接，没有自动交叉核验或把多个引用合并到同一卡片的功能。
